# SRS СЕРВИСА #РЕКЛ V0.51

**Software Requirements Specification**

Источник: `260611-SRS-SERVISA-REKL-V0.51-6.docx`

## 1. Назначение

Сервис #РЕКЛ обеспечивает:
- регистрацию рекламаций;
- обработку рекламаций;
- модерацию контента;
- разрешение конфликтов;
- эскалацию ответственности;
- фиксацию решений;
- восстановление доверия;
- интеграцию с поручительством и страхованием.

## 2. Scope

- **2.1 Реестр рекламаций** — учет всех рекламаций
- **2.2 Панель рекламаций** — рабочее место модератора
- **2.3 Система эскалации** — передача между уровнями
- **2.4 Система решений** — фиксация результатов
- **2.5 Система поручительства** — интеграция с #ДЕПО
- **2.6 Система страховых случаев** — интеграция с #СТРХ
- **2.7 История и аудит** — полное протоколирование

## 3. Роли

| Роль | Описание |
|---|---|
| Автор | Владелец объекта |
| Заявитель | Создает рекламацию |
| Ответчик | Субъект, к которому предъявлена рекламация |
| Координатор | Модератор сообщества |
| Уполномоченный | Модератор территории |
| Поручитель | Модератор финансовых рекламаций |
| Модератор Когитеки | Модератор системных деревьев знаний |
| Супервизор | Высший индивидуальный модератор |
| Правление | Коллегиальный орган |
| Вече | Высшая инстанция |

## 5. Жизненный цикл

```
DRAFT → REGISTERED → ACCEPTED → IN_REVIEW → DECISION_MADE → RESOLVED → CLOSED
                                     ↓
                                ESCALATED
```

## 6. Статусы (enum)

| Статус | Описание |
|---|---|
| `draft` | Черновик |
| `registered` | Зарегистрирована |
| `accepted` | Принята |
| `in_review` | Рассматривается |
| `waiting_response` | Ожидается ответ |
| `resolved` | Разрешена |
| `escalated` | Эскалирована |
| `closed` | Закрыта |
| `cancelled` | Отозвана |

## 8. Бизнес-правила

- **BR-01** Любой субъект может подать рекламацию.
- **BR-02** Любая рекламация должна иметь ответственного.
- **BR-03** Любая рекламация имеет историю.
- **BR-04** Удаление рекламаций запрещено. Только архивирование.
- **BR-05** Ответчик имеет право дать пояснение.
- **BR-06** Ответственный обязан принять решение либо выполнить эскалацию.
- **BR-07** Эскалация фиксируется как событие.
- **BR-08** Любое решение должно иметь автора.
- **BR-09** Любое решение должно иметь обоснование.
- **BR-10** После закрытия рекламации данные становятся неизменяемыми.

## 23. Definition of Done

- DDL развернут.
- API работает.
- UI работает.
- Acceptance Pack проходит.
- Все события журналируются.
- Эскалация функционирует.
- Решения неизменяемы.
- Поддерживается история рекламации.
- Выполнена интеграция с субъектной моделью V0.51.
- Панель рекламаций используется как единый интерфейс модерации HomoNet.
