## Главное расхождение старого ТЗ с HomoNet

Старая «модераторская панель» реализует классическую модель форумов (Reddit/Discourse/GitHub):

```
Пользователь → Жалоба → Модератор → Решение
```

HomoNet построен на другой модели:

```
Субъект → Рекламация → Ответственный контур → Решение → Эскалация → Восстановление доверия
```

**Вывод**: нужна не модераторская панель, а сервис **#РЕКЛ**, а `/moderation` становится одним из его интерфейсов.

## Что оставляем из старого черновика

## Что противоречит и что заменено

### Проблема №1 — модерация привязана к `auth_user`

**Было**: права на `auth_user` + `user_role`.
**Стало**: субъектная модель V0.51 — `subject` / `role_assignment`. Модератор — не пользователь, а **роль субъекта**.

### Проблема №2 — единая роль `moderator`

**Было**: `user_role(role='moderator')`.
**Стало**: иерархия ролей Автор → Координатор → Уполномоченный → Поручитель → Модератор Когитеки → Супервизор → Правление → Вече. Ответственность через `reclamation_participant.role` + `current_responsible_subject_id`.

### Проблема №3 — нет дерева эскалации

**Было**: `report → moderator → resolve`.
**Стало**: `reclamation_escalation` с явным `from_level → to_level` (0..6), интеграция с #ДЕПО.

### Проблема №4 — нет участия автора

**Было**: автор объекта — предмет, а не участник.
**Стало**: `reclamation_response` (accept/reject/explain/apologize/counter/withdraw) — автор может признать, возразить, исправить, приложить пояснение.

### Проблема №5 — нет автоматических рекламаций контекста

**Было**: рекламация только от пользователя.
**Стало**: `source_type` enum (`user/auto/moderator/system/appeal`) + `reclamation_context_rule` / `reclamation_context_trigger`. Правило `THANKA_IN_FOREIGN_TREE` — референсный кейс.

## Утверждённые архитектурные решения (5 штук)

| # | Решение |
|---|---|
| 1 | **Сохраняем UI `/moderation`** — понятное пользователю название, становится фасадом сервиса #РЕКЛ |
| 2 | **Backend-модуль**: `backend/modules/reclamation` (URL API `/api/v051/rekl/...`) |
| 3 | Таблица `report` из старого draft — не применяется (мигрируем сразу на `reclamation`) |
| 4 | **Новые типы рекламаций**: `content/context/behavior/transaction/governance/system` — сервис обслуживает Когитеку, сделки, голосования, проекты, сообщества |
| 5 | **Инвариант**: любая рекламация должна иметь ответственного субъекта — новый институциональный инвариант HomoNet |

## Итог

Из внешне «частной» задачи модераторской панели получен полноценный институциональный сервис HomoNet, согласованный с:

- концепцией ИП V0.51;
- генотипом G1–G16;
- ER V0.51;
- субъектной моделью Person → Subject;
- сервисами #ДЕПО, #ГЛАС, #ВЕЧЕ;
- принципом делократии;
- финансовой моделью сделок.

Модераторская панель становится **первым пользовательским интерфейсом** одного из базовых сервисов HomoNet.
