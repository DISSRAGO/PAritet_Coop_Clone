# VISION СЕРВИСА #РЕКЛ V0.51

**Сервис рекламаций, ответственности и восстановления доверия HomoNet**

Источник: `260611-VISION-SERVISA-REKL-V0.51-8.docx`

## 1. Назначение

Сервис #РЕКЛ предназначен для фиксации несогласия, рассмотрения рекламаций, разрешения конфликтов, восстановления доверия и защиты среды Инфопоселения.

Главная задача — **не наказание виновного, а сохранение среды сотрудничества**.

## 2. Миссия

Создать механизм справедливого разрешения конфликтов, при котором каждый субъект имеет право:
- быть услышанным;
- выразить несогласие;
- получить рассмотрение своей рекламации;
- получить мотивированное решение;
- обжаловать решение;
- восстановить нарушенные права и отношения.

## 3. Основная идея

Наличие конфликтов не является проблемой. Проблемой является отсутствие механизмов их разрешения. Сервис #РЕКЛ — институциональный механизм самоочищения и самовосстановления среды Инфопоселения.

## 5. Базовые понятия

| Термин | Определение |
|---|---|
| **Несогласие** | Субъективное мнение участника о нарушении интересов/прав/обязательств/контекста |
| **Рекламация** | Формально зарегистрированное событие несогласия, требующее рассмотрения |
| **Конфликт** | Совокупность взаимосвязанных рекламаций между субъектами |
| **Решение** | Зафиксированный результат рассмотрения рекламации |
| **Эскалация** | Передача рекламации на следующий уровень ответственности |
| **Восстановление доверия** | Действия по устранению причин конфликта и возвращению к сотрудничеству |

## 6. Принципы сервиса

- **R1. Право на несогласие** — каждый субъект имеет право выразить несогласие.
- **R2. Право на рассмотрение** — ни одна рекламация не может быть проигнорирована.
- **R3. Ответственность за решение** — каждая рекламация должна иметь ответственного субъекта.
- **R4. Протоколирование** — все действия по рекламации фиксируются.
- **R5. Эскалация** — нерешенная рекламация автоматически поднимается на следующий уровень.
- **R6. Справедливость** — рассмотрение производится независимо от статуса сторон.
- **R7. Восстановление среды** — целью является восстановление сотрудничества.

## 7. Типы рекламаций

| Тип | Enum | Пример |
|---|---|---|
| Контентные | `content` | Спам, оскорбления, ложная информация, нарушение правил |
| Контекстные | `context` | Тханка в чужом дереве, якорь в чужой тханке, пост в чужой ленте |
| Поведенческие | `behavior` | Злоупотребление полномочиями, токсичность, саботаж |
| Экономические | `transaction` | Невыполнение договора, срыв сроков, некачественный продукт |
| Организационные | `governance` | Решение координатора, назначение ролей, исключение участников |
| Системные | `system` | Автоматически по правилам контекста, контроля обязательств |

## 8. Уровни ответственности

| Уровень | Роль | Комментарий |
|---|---|---|
| 0 | Автор объекта | Первичная ответственность |
| 1 | Координатор сообщества | Владелец дерева группы |
| 2 | Уполномоченный кооперативного участка | Владелец сайта |
| 3 | Поручитель | Контур сервиса #ДЕПО |
| 4 | Супервизор | Владелец Инфоша |
| 5 | Правление | Коллегиальный орган |
| 6 | Вече | Высшая инстанция |

## 10. Жизненный цикл

```
Создана → Принята → Рассматривается → Решение принято → Исполнена → Закрыта
                                                       ↓
                                                  Эскалирована → Передана следующему
```

## 11. Возможные решения

Отклонение / признание / исправление / предупреждение / временное ограничение / перемещение объекта / архивирование / компенсация / страховая выплата / отзыв полномочий / передача на голосование / передача на Вече.

## 17. Формула сервиса

```
Несогласие → Рекламация → Обсуждение → Решение → Исправление → Восстановление доверия → Развитие среды
```

## 18. Роль в Инфопоселении

Сервис #РЕКЛ — иммунная система Инфопоселения:
- #КОГИ формирует знания;
- #ДЕЛО создает результаты;
- #СЧЕТ обеспечивает обмен;
- **#РЕКЛ обеспечивает устойчивость среды.**

Без сервиса #РЕКЛ невозможны долговременное доверие, кооперация и развитие Сектора солидарной экономики.
